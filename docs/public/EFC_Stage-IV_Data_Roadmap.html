Energy-Flow Cosmology — Stage-IV Data Roadmap

Morten Magnusson · Symbiose Research, Sandnes, Norway · ORCID: 0009-0002-4860-5095 · April 2026 · CC-BY-4.0

One sentence: This roadmap maps every major Stage-IV data release (2026–2031+) to the specific EFC prediction, observable, regime, and kill criterion it will test — so that no result arrives without a pre-registered expectation.

0. Purpose and Governance

The Validation Ledger documents what has been tested. The White Paper Series documents what EFC predicts. This roadmap documents when and how those predictions will be confronted with data.

Governance rule: All entries in this roadmap are frozen at the time of publication. No post-hoc addition of tests after data release is permitted. New tests may be added to future versions of this roadmap before the relevant data becomes public. Additions are versioned and timestamped.

Statistical conventions

All significance levels (σ) in this document are frequentist, computed as √Δχ² for nested models or as the equivalent Gaussian significance of a p-value for non-nested comparisons. Unless stated otherwise, tests are two-sided except where a directional prediction is specified (e.g., μ < 1, α < 0), in which case one-sided significance is reported and explicitly marked. Model comparison uses Δχ² and ΔAIC as primary metrics; Bayesian evidence ratios (ln B) are reported where available but are not used as primary decision criteria due to prior sensitivity.

3. Statistical Evaluation Framework

All quantitative tests in this roadmap are evaluated using the following framework. The purpose is to ensure that thresholds are reproducible and not arbitrary.

3.1 Likelihood and Model Comparison

Element Specification
Likelihood form Gaussian likelihood assumed for all Stage-IV probes unless survey documentation specifies otherwise. For cosmic shear: L ∝ exp(−½ ΔdT C−1 Δd) where d is the data vector and C the covariance.
Data vectors Probe-specific: shear Cℓ (Euclid); P(k) multipoles + BAO (DESI); fσ8(z) (RSD compilation); CMB lensing Cℓφφ (Planck/ACT/SPT). Each data vector is defined by the survey collaboration.
Covariance Survey-provided covariance matrices are used in all cases. EFC does not introduce independent covariance estimates. Where survey covariance is unavailable (e.g., pre-release forecasts), Fisher matrix projections from official survey specifications are used and explicitly flagged.
Model comparison Primary: Δχ² between EFC and ΛCDM (nested where applicable, profile likelihood where not). Secondary: ΔAIC = Δχ² + 2Δk (penalises extra parameters). Bayesian evidence (ln B) reported where posterior sampling is performed but not used as primary criterion.
Parameter handling EFC parameters (β, T(a), zt) are frozen in the Global Parameter Registry (Ledger §0.2). Standard cosmological parameters (Ωm, H₀, σ₈, ns) are marginalised over with Planck 2018 + BAO priors unless stated otherwise. No probe-specific re-tuning is permitted.
Threshold interpretation Kill criteria (KC) are evaluated as: if the best-fit EFC parameter falls within the stated null range at the stated confidence level (e.g., |α| < 0.1 at 3σ), the sector is falsified. The confidence level is determined by the posterior width from the survey likelihood, not by an EFC-internal estimate.

5. Blinding and Analysis Protocol

The integrity of pre-registered predictions depends on demonstrable separation between prediction and analysis. The following protocol governs all EFC confrontations with Stage-IV data.

5.1 Prediction Integrity

Element Implementation
Sealed predictions Two cryptographic freezes (SHA-256 hashes) deposited before data release. Hash 7a850cfa... (2026-02-18) and dbccda15... (2026-02-21). Full parameter sets recoverable from hash verification.
Kill criteria frozen KC1–KC5 thresholds defined in White Paper Series Part 3 and deposited via Figshare DOI (31970904) before any Stage-IV data release.
Parameter freeze Global Parameter Registry (Ledger §0.2) governs all shared parameters. No parameter may be modified between prediction deposit and analysis completion. Violations void the test.

5.2 Analysis Execution

Element Implementation
Pipeline versioning All analysis code is maintained in the EFC GitHub repository (github.com/supertedai/EFC). The git commit hash at the time of analysis is recorded in the results paper. No code modifications are permitted after data unblinding.
Survey pipelines For survey-provided likelihoods (Euclid, DESI, Rubin), the official pipeline version is used without modification. The pipeline version and any configuration choices are documented.
No post-hoc tuning After data unblinding, the following are prohibited: (i) modifying EFC parameters, (ii) changing scale cuts, (iii) switching likelihood forms, (iv) adding or removing probes. If any of these are found necessary, the analysis is restarted as a new, clearly labeled exploratory analysis and does not count toward the pre-registered test.
Reporting obligation All results — including failures and null detections — are reported in the Validation Ledger within one revision cycle. Suppression of unfavorable results is explicitly prohibited under the EFC validation protocol (Core Lock v1.0).

6. Degeneracy and Discriminant Structure

Several non-EFC physical effects can produce signals similar to EFC predictions. This section identifies the dominant degeneracies and the observational channels that break them. The key discriminant is that EFC predicts a specific combination of μ < 1, Σ > 1, and η ≈ 1.10 simultaneously — a pattern that is rare or absent in most competing models.

7. Failure Response Protocol

Kill criteria, action-level conditions, and standing falsification conditions have different consequences. This hierarchy ensures that responses to data are pre-determined and not subject to post-hoc rationalisation.

Level Conditions Consequence if Triggered Scope of Revision
Kill Criterion (KC) KC1–KC5 Hard falsification of the specified sector. The sector is formally abandoned. No revision pathway exists within the current EFC framework. Documented in Ledger §3.2 (Historical Falsifications) within one revision cycle. Sector-specific: KC1 kills growth sector; KC3 kills S₈ channel; etc. Other sectors may survive.
Action-Level (FA) FA1–FA6 Theory-level rejection of the EFC Relativistic Action in its current form. The variational action must be revised or replaced. Downstream predictions (μ, Σ, η values) are invalidated until a new action is derived and tested. Perturbation sector only. Galactic sector (SPARC, Graph-AQUAL) is not affected. Background sector is already closed.
Standing Falsification (F) F1–F6 Tension / revision trigger. The affected channel is disfavoured but the overall framework may survive if other channels compensate. A formal revision is required, documented as a model update (not suppressed). Channel-specific. E.g., F1 (ISW) disfavours background-driven growth but does not kill perturbation sector. F5 (rotation curves) would require Graph-AQUAL revision.

7.1 Compound Failure Rules

Scenario Interpretation
1 KC triggered, others pass Sector falsified. Remaining framework viable but reduced in scope. Documented as partial falsification.
2+ KC triggered Framework-level crisis. If growth + lensing + slip all fail, EFC perturbation sector is abandoned. Galactic sector evaluated independently.
KC passes but FA fails Empirical signal survives but theoretical derivation is wrong. Action must be revised to reproduce the observed (μ, Σ, η) values. This has precedent: F7 was passed only after the Relativistic Action replaced the naïve GRAV extrapolation.
All KC pass, all FA pass Confirmation ladder advances. Does not constitute proof — only survival under increasingly stringent tests.
Sealed prediction within 1σ Strong support. Reported as pre-registered confirmation.
Sealed prediction within 2σ Consistent. No action required.
Sealed prediction beyond 3σ Prediction falsified. Documented in Ledger. Parameter re-estimation from new data is permitted as an exploratory update (clearly labeled, not pre-registered).

Governance commitment: The failure response protocol is frozen at publication. No reclassification of KC → F or FA → F is permitted after data release. Historical falsifications (Ledger §3.2) demonstrate that EFC has already applied this protocol to itself: two model versions and one structural gap have been formally discarded.
