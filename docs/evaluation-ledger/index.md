# EFC Evaluation Ledger

> **Purpose**: Define the global function that turns per-test outputs into a
> single, falsifiable verdict for the EFC framework. No semantic verdicts
> ("looks consistent") — only quantitative thresholds and a documented
> aggregation rule.

---

## 1. Verdict thresholds (global)

Applied per individual test result before aggregation:

| Verdict   | Criterion                |
|-----------|--------------------------|
| `PASS`    | `|Δχ²|` < 1              |
| `TENSION` | 1 ≤ `|Δχ²|` < 9 (1–3σ)   |
| `FAIL`    | `|Δχ²|` ≥ 9 (>3σ)        |

Tests with vocabulary `COLLAPSED` from `validation-ledger` are mapped to `FAIL`.
Tests with `MARGINAL` are mapped to `TENSION` if `|Δχ²|` is unavailable.

---

## 2. Global score function

```
EFC_score = Σᵢ wᵢ · Δχ²ᵢ
```

Where the sum runs over **inference-grade tests only** (i.e. tests with a
`likelihood-ledger` entry of `status ∈ {executed, frozen}`).

Weights `wᵢ` are declared in `data/evaluation.json` per test_id.
Default `wᵢ = 1` if not declared.

### Bayesian variant (preferred when posteriors available)

```
ln K_total = Σᵢ ln K_i      (sum of log-Bayes factors EFC vs ΛCDM per test)
```

Reported alongside frequentist score whenever `evidence` is in the
likelihood entry's `outputs`.

---

## 3. Falsification rule (system-level)

EFC is **falsified at the system level** if either:

1. Any **kill criterion** test (KC1–KC6) returns `FAIL`, OR
2. The global posterior odds `K_total` against ΛCDM exceeds `1:100`
   (decisive against, by Jeffreys' scale)

Failure of a non-kill-criterion test produces `TENSION`, not falsification.

---

## 4. Falsification status ≠ Model preference

These are recorded as **two separate fields** in
`data/evaluation.json["current_state"]`:

| Field                  | Means                                                            |
|------------------------|------------------------------------------------------------------|
| `falsification_status` | `non-falsified` \| `tension` \| `falsified`                      |
| `model_preference`     | per `ΔAIC` / `ln K`: `prefers_efc` \| `neutral` \| `prefers_lcdm` |

Both must be reported. Conflating them was an explicit gap in the audit.

---

## 5. Per-test weight declaration

```json
{
  "test_id": "s8_growth_fsigma8_2026",
  "weight": 1.0,
  "rationale": "Primary observable for μ<1 prediction"
}
```

Weights default to 1.0. Non-unit weights require a `rationale` string —
no silent down-weighting of tensions.

---

## 6. Atlas linkage

The Atlas defines the model space (parameter regions for EFC). This ledger
consumes from Atlas via `data/atlas-link.json`:

```json
{
  "atlas_ref": "<TBD: actual atlas path>",
  "consumed_fields": ["allowed_region", "excluded_region"],
  "purpose": "Map per-test posteriors back into Atlas viability regions",
  "modifies_atlas": false
}
```

**This ledger does not write to Atlas.** When inference results land,
a separate downstream step (TBD) projects them onto Atlas regions for
visualization. That step lives outside this ledger.

---

## 7. Reporting

Every release of the evaluation ledger MUST publish:

- `EFC_score` (frequentist sum)
- `ln K_total` (Bayesian, when available)
- `falsification_status`
- `model_preference`
- List of currently `TENSION` tests (with test_id and Δχ²)
- List of currently `FAIL` tests (with test_id and Δχ²)

In `data/evaluation.json["current_state"]`, regenerated by the sync hook.
